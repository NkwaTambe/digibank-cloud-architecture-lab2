Lab 2: Enterprise Design Patterns

Stateless Session Beans (@Stateless)

Encapsulates business operations with automatic container-managed transactions (CMT). Ensures thread safety and transaction rollback on exception.

@Stateless
public class TransactionService {
  @PersistenceContext
  private EntityManager em;
}

Contexts & Dependency Injection (@Inject)

CDI manages lifecycle and dependency injection across REST resources and EJBs cleanly without manual factory boilerplate.

@Path("/transactions")
public class TransactionRest {
  @Inject
  private TransactionService service;
}

Lab 2: Real‑world Challenges & Solutions

  • Class‑loader conflicts: WildFly modules required explicit jboss.modules.system.pkgs entries.
  • Schema migrations: Flyway scripts had to be ordered to avoid data loss during module refactors.
  • Transaction boundaries: EJB CMT vs. CDI @Transactional mis‑configurations caused lazy‑load errors.
  • Networking: Docker bridge networking needed port mapping (5434) to avoid collision with host PostgreSQL.
  • Swagger UI not loading: Required enabling microprofile-openapi feature in standalone.conf.

Lab 3: Spring Boot Monolith Slide 24 / 42

Challenge 1: Multi-Module Component Scanning

ISSUE

Main application class in digibank-app failed to discover Spring beans and JPA entities located in sibling modules (e.g., digibank-customer, digibank-account) during startup.

SOLUTION

Configured explicit package root scanning annotations on the main application boot class:

@ComponentScan(basePackages = "com.digibank") @EntityScan(basePackages = "com.digibank") @EnableJpaRepositories(basePackages = "com.digibank")
Lab 3: Key Oral Challenges Solved Slide 25 / 42

Challenge 2: `@PathVariable` Reflection Name Resolution

ISSUE

HTTP 500 runtime errors on WildFly when invoking endpoints like /api/customers/{id} because Java compiler omitted method parameter names from class bytecodes.

SOLUTION

Injected the <parameters>true</parameters> flag into the parent maven-compiler-plugin configuration to preserve method reflection parameter names.

<plugin> <groupId>org.apache.maven.plugins</groupId> <artifactId>maven-compiler-plugin</artifactId> <configuration><parameters>true</parameters></configuration> </plugin>
Lab 3: Key Oral Challenges Solved Slide 26 / 42

Challenge 3: Column Naming Strategy Mismatch

ISSUE

Lab 2 `init.sql` created camelCase database columns (e.g., firstName) which clashed with Hibernate 6 default physical naming strategy that translates properties to snake_case (e.g., first_name).

SOLUTION

Created a dedicated db/init-spring.sql script for database/user creation only, allowing Hibernate's spring.jpa.hibernate.ddl-auto=update to generate matching physical tables automatically.

Lab 3: Key Oral Challenges Solved Slide 27 / 42

Challenge 4: External WAR Deployment on WildFly

ISSUE

Deployment conflicts on WildFly due to embedded Tomcat starter classes bundling servlet containers and logging jars inside the WAR package.

SOLUTION

Marked embedded web container dependencies as <scope>provided</scope> and extended SpringBootServletInitializer in the primary boot class.

<dependency> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-tomcat</artifactId> <scope>provided</scope> </dependency>
Lab 3: Key Oral Challenges Solved Slide 28 / 42

Challenge 5: Idempotent REST Script Testing

ISSUE

Automated execution of setup-spring.sh threw duplicate key SQL constraints on unique fields (email, account number) when re-run multiple times.

SOLUTION

Updated script cURL payloads to append dynamic epoch timestamps and random suffixes to test entities, ensuring 100% idempotent test passes.

EMAIL="john.doe.$(date +%s)@digibank.com" ACC_NUM="ACC-$(date +%s)"

Why Decompose the Monolith?

Architectural Drivers

  • Independent Scalability: Scale high-volume transaction processing independently of customer management.
  • Fault Isolation: Notification service crashes do not disrupt core balance consultations.
  • Database per Service: Eliminates shared database bottlenecks and tight schema coupling.
  • Autonomous Deployments: Update compliance rules without re-deploying the full banking platform.

Lab 4: Cloud-Native Microservices Slide 33 / 42

Fault Tolerance & Resilience4j

Circuit Breaker Pattern

Prevents cascading failures across distributed REST boundaries when invoking remote services (e.g., Compliance or Account).

  • CLOSED: Normal RPC executions pass through.
  • OPEN: Short-circuits failing remote endpoints.
  • HALF-OPEN: Probes remote service recovery.

Fallback Mechanism

Executes safe default business fallback when remote service times out or fails.

@CircuitBreaker(name = "complianceCB", fallbackMethod = "complianceFallback") public boolean validateTransfer(BigDecimal amt) { return complianceClient.validate(amt); }

Key Engineering Lessons Learned

  • Clean Domain Boundaries Pay Off: Maintaining strict module separation in Labs 2 & 3 enabled seamless microservice decomposition in Lab 4.
  • Framework Interoperability: Business entities and validation logic transfer cleanly between Jakarta EE and Spring Boot.
  • Distributed Systems Require Resilience: Monolithic in-memory calls must be replaced with Circuit Breakers and Sagas in cloud environments.
  • DevOps Automation is Non-Negotiable: Docker Compose and shell orchestration scripts (`setup-spring.sh`) ensure repeatable deployments.
